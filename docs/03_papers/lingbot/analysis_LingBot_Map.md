## 2. 研究背景与动机

### 2.1 流式3D重建的核心挑战

**流式3D重建（Streaming 3D Reconstruction）** 旨在从视频流中实时恢复三维信息（如相机位姿和点云），这对以下应用至关重要：

- **自动驾驶**：实时构建周围环境的三维地图
- **增强现实（AR）**：将虚拟对象准确锚定到真实世界
- **机器人导航**：使机器人理解其所处空间
- **无人机自主飞行**：实时感知和避障

流式3D重建需要同时满足三个要求：
1. **几何精度（Geometric Accuracy）**：重建结果必须精确
2. **时间一致性（Temporal Consistency）**：跨时间的估计必须连贯
3. **计算效率（Computational Efficiency）**：必须实时运行

### 2.2 SLAM的启示与传统方法的局限

**SLAM（Simultaneous Localization and Mapping，同时定位与建图）** 是处理这一问题的经典框架。传统SLAM系统通过以下方式维持一致性：

- **关键帧（Keyframe）选择**：选择代表性帧进行优化
- **回环检测（Loop Closure）**：检测之前访问过的位置以校正累积误差
- **全局光束平差（Bundle Adjustment）**：联合优化所有相机位姿和3D点

但这些方法的局限在于：
- 高度依赖手工设计的特征和优化规则
- 在低纹理、动态或重复纹理场景中容易失败
- 计算复杂度随序列长度超线性增长

### 2.3 现有3D基础模型在流式场景下的不足

近年来，3D基础模型（如 DUSt3R、MASt3R、VGGT [81]）在从少量图像恢复3D结构方面取得了显著进展。然而，将它们直接应用于流式场景面临挑战：

- **轨迹漂移（Trajectory Drift）**：随着序列增长，位姿估计误差累积导致重建结果逐渐偏离真实轨迹。
- **精度退化**：在长序列中，重建精度显著下降。
- **计算开销增长**：处理长序列时计算成本可能不可接受。

**常见失败模式**：
- 明显的轨迹漂移（轨迹逐渐偏离真值）
- 重建精度下降
- 计算复杂度随时间不可持续增长

## 3. 核心贡献

LingBot-Map 是一个**前馈式（feed-forward）3D基础模型**，专门为流式数据场景设计，其核心是**GCT（Geometric Context Transformer，几何上下文Transformer）架构**。

关键贡献包括：

1. **GCA（Geometric Context Attention，几何上下文注意力）机制**
   - 一种精心设计的注意力机制，集成了三种互补的上下文：
     - **锚点上下文（Anchor Context）**：解决坐标定位问题
     - **位姿参考窗口（Pose-Reference Window）**：提供稠密几何线索
     - **轨迹记忆（Trajectory Memory）**：处理长程漂移校正

2. **紧凑的流式状态设计**
   - 保持流式状态紧凑（~80× 复杂度降低），同时保留丰富的几何上下文。
   - 复杂度对比：GCA ~7×10⁴ vs 因果注意力 ~5×10⁶（当 n=3, k=16, T=10000）。

3. **渐进式视图训练（Progressive View Training）**
   - 解决长序列训练中早期误差传播的问题。
   - 从短序列逐步扩展到长序列。

4. **两种互补的推理模式**
   - **Direct 模式**：逐帧直接预测，轨迹精度最高。
   - **VO（Visual Odometry）模式**：使用关键帧窗口 + Sim(3) 对齐，适合极长序列。

5. **实时推理**
   - 约 **20 FPS** @ 518×378 分辨率。
   - 支持超过 **10000 帧**的长序列。
   - 使用 Paged KV-cache 和 FlashInfer 进行高效推理。

## 4. 方法详细描述

### 4.1 GCT（几何上下文Transformer）整体架构

GCT 架构的核心思想是：在每一帧的推理中，模型通过注意力机制有选择地访问三类几何上下文，而非像标准 Transformer 那样对所有历史帧进行全局注意力。

**GCT 架构总览**：

```
  输入视频流 (帧序列)
  o_1, o_2, o_3, ..., o_T  (T > 10000)
       │
       ▼
┌──────────────────────────────────────────────────────────────────┐
│                   GCT (Geometric Context Transformer)              │
│                                                                   │
│   每帧处理:                                                        │
│   ┌──────────┐                                                    │
│   │ 图像编码器 │──▶ 特征 token f_t                                 │
│   └──────────┘                                                    │
│         │                                                          │
│         ▼                                                          │
│   ┌──────────────────────────────────────────────────────────┐   │
│   │              GCA (Geometric Context Attention)             │   │
│   │                                                             │   │
│   │   当前帧 f_t 可关注:                                         │   │
│   │                                                             │   │
│   │   ┌─────────────┐  ┌───────────────┐  ┌──────────────────┐ │   │
│   │   │ 锚点上下文    │  │ 位姿参考窗口   │  │  轨迹记忆        │ │   │

│   │   │             │  │              │  │                  │ │   │
│   │   │ ● ● ●       │  │ ●●●●●●●●●●●●●●│  │ ═══════════════ │ │   │
│   │   │ 均匀采样     │  │ 滑动窗口      │  │ 长程校正信号    │ │   │
│   │   │             │  │              │  │                  │ │   │
│   │   │ 作用:        │  │ 作用:         │  │ 作用:            │ │   │
│   │   │ 全局坐标定位 │  │ 局部稠密几何  │  │ 漂移抑制        │ │   │
│   │   └─────────────┘  └───────────────┘  └──────────────────┘ │   │
│   │                                                             │   │
│   │   复杂度: ~7×10⁴ (vs 因果注意力 ~5×10⁶ → ~80× 降低)        │   │
│   └──────────────────────────────────────────────────────────┘   │
│                              │                                     │
│              ┌───────────────┼───────────────┐                    │

│         │稠密深度图│    │camera→world│   │帧间变换   │               │
│         └────────┘    └──────────┘    └──────────┘               │
└──────────────────────────────────────────────────────────────────┘

       ▼
  实时输出 @ ~20 FPS:
  深度图 + 相机轨迹 + 点云 (流式更新)
```

**架构解读**：

GCT 的设计围绕一个核心矛盾展开：模型需要同时满足**全局一致性**（不能漂移）和**局部精度**（帧间运动要准），而标准 Transformer 的全局注意力在这两个目标之间无法取得平衡——要么全关注（~5×10⁶ 复杂度，不可扩展），要么只关注近期（丢失全局参考）。GCA 的三分法将注意力预算精确分配到三个互补的几何推理任务上：

- **锚点上下文**像 GPS 卫星——稀疏但全球覆盖，提供绝对坐标参考。仅用 n=3 个锚点帧就对整个序列构建了稳定的世界坐标系。
- **位姿参考窗口**像局部里程计——稠密但范围有限（k=16 帧），捕捉精细的相对运动。窗口内保持全连接，确保短时运动估计的平滑性。
- **轨迹记忆**像回环检测——压缩了整个历史轨迹的关键几何信息，当模型"走偏"时提供校正信号。

三者的计算开销加起来仅为全局因果注意力的 ~1/80，这使得 20 FPS 的实时推理在超过 10000 帧的长序列上成为可能。

**架构组成**：
1. **图像编码器**：将每一帧 RGB 图像编码为特征 token。
2. **GCA 注意力层**：在 Transformer 解码器中使用 GCA 替代标准注意力。
3. **多任务预测头**：
   - **深度预测头**：输出每帧的稠密深度图
   - **绝对位姿预测头**：输出相机到世界坐标系的绝对位姿（旋转 + 平移）
   - **相对位姿预测头**：输出相邻帧之间的相对位姿变化

**坐标系**：
- 使用**相机到世界（camera-to-world）**坐标系。
- 这使得模型可以直接输出每个相机在世界中的绝对位置。

### 4.2 GCA（几何上下文注意力）：三大注意力机制

GCA 是 LingBot-Map 最核心的技术创新。它将标准 Transformer 的因果注意力分解为三个专业的上下文窗口：

#### （1）锚点上下文（Anchor Context）

**解决的问题**：坐标定位（Coordinate Grounding）

**机制**：
- 在整个序列中均匀选择少量**锚点帧（anchor frames）**。
- 每一帧始终可以关注这些锚点帧。
- 锚点帧提供了全局坐标参考，防止模型"迷失"在世界坐标系中。

**类比**：类似于 GPS 系统中的参考卫星——提供了全局坐标系中的定位基准。

**效果**：
- 防止长序列中的全局漂移。
- 提供稳定的世界坐标系参考。

#### （2）位姿参考窗口（Pose-Reference Window）

**解决的问题**：提供稠密几何线索（Dense Geometric Cues）

**机制**：
- 保持一个**滑动窗口**（大小为 `k`，论文中 k=16），包含最近的帧。
- 当前帧可以关注窗口内的所有帧。
- 窗口内保持密集的帧间连接，以捕捉精细的相对运动和几何关系。

**类比**：类似于视觉里程计中的局部窗口优化——提供短时间内的精确相对运动估计。

**效果**：
- 捕捉精细的运动模式
- 提供短时局部一致性
- 窗口大小在精度和计算开销之间取得平衡

#### （3）轨迹记忆（Trajectory Memory）

**解决的问题**：长程漂移校正（Long-range Drift Correction）

**机制**：
- 维护一个压缩的**轨迹记忆（Trajectory Memory）**，存储历史轨迹的关键信息。
- 当前帧通过注意力查询轨迹记忆，校正累积误差。

**类比**：类似于 SLAM 中的回环检测——提供长时一致性约束。

**效果**：
- 抑制长序列中的轨迹漂移
- 提供全局时间一致性

#### 复杂度分析

GCA 的关键优势在于**计算复杂度**的显著降低：

| 注意力类型 | 复杂度（T=10000, k=16, n=3） |
|-----------|---------------------------|
| 标准因果注意力（Causal） | ~5 × 10⁶ |
| GCA（Three Contexts） | ~7 × 10⁴ |
| **复杂度降低** | **~80×** |

这使得 LingBot-Map 能够在保持几何精度的同时，以实时速度处理极长序列。

### 4.3 渐进式视图训练（Progressive View Training）

训练一个端到端的流式3D重建模型在长序列上极具挑战性：早期帧的位姿误差会沿序列传播并放大。

**渐进式训练策略**：
1. **第一阶段**：在短序列上训练（如 50-100 帧），此时误差传播效应较弱。
2. **第二阶段**：逐步增加序列长度（200 → 500 → 1000 → ... 帧）。
3. **第三阶段**：在完整长序列上训练。

**类比**：类似于课程学习（Curriculum Learning）——先学简单的短序列，再逐步过渡到复杂的长序列。

**效果**：
- 避免训练早期的发散
- 使模型逐步适应长序列中的误差累积
- 提升最终模型的稳定性和精度

### 4.4 推理系统设计

LingBot-Map 的推理系统采用了多项工程优化以实现实时性能：

| 优化项 | 描述 |
|--------|------|
| **Paged KV-cache** | 分页式的键值缓存管理，高效利用 GPU 显存 |
| **FlashInfer** | 使用 FlashInfer 库进行高效的注意力计算 |
| **上下文并行（Context Parallelism）** | 使用 Ulysses 风格的维度并行（dim=16），将长序列分布到多 GPU |
| **流式状态管理** | 紧凑的 GCA 上下文设计使得流式状态开销极小 |

**实测性能**：
- 推理速度：约 **20 FPS**
- 输入分辨率：**518 × 378**
- 支持序列长度：**> 10000 帧**

## 5. 推理模式

LingBot-Map 提供了两种互补的推理模式，用户可根据场景需求选择。

### 5.1 Direct模式

**工作方式**：
- 每一帧直接输出**绝对相机位姿**和**稠密深度图**。
- 不对预测结果进行任何后处理对齐。
- 预测误差完全来自模型逐帧推理的累积。

**优点**：
- 轨迹精度更高（避免了窗口间对齐引入的额外误差）。
- 更简洁的实现。

**缺点**：
- 在极长序列（>10000 帧）中，微小的逐帧误差会累积为明显的全局漂移。

**适用场景**：
- 中等长度的序列（< 5000 帧）。
- 对轨迹精度要求最高的应用。

### 5.2 VO（视觉里程计，Visual Odometry）模式

**工作方式**：
1. 将序列划分为**关键帧窗口（keyframe windows）**。
2. 在每个窗口内使用模型进行局部重建。
3. 在窗口之间使用 **Sim(3)（相似变换）对齐** 将局部重建拼接为全局一致的结果。

**Sim(3) 对齐**：
- Sim(3) 是包含缩放因子的刚体变换（7个自由度：3旋转 + 3平移 + 1缩放）。
- 通过在相邻窗口的重叠区域进行点云配准来计算 Sim(3) 变换。

**优点**：
- 在极长序列中更好地控制全局漂移。
- 计算效率更高（每个窗口独立处理）。

**缺点**：
- 窗口间对齐引入额外误差。
- 轨迹精度低于 Direct 模式（误差随窗口数增加而复合）。

**适用场景**：
- 极长序列（> 5000 帧）。
- 对绝对轨迹精度要求相对宽松但需要全局一致性的应用。

### 5.3 两种模式的权衡

| 维度 | Direct 模式 | VO 模式 |
|------|------------|---------|
| 轨迹精度 | **更高** | 较低（窗口间对齐引入误差） |
| 长序列漂移 | 存在（逐帧误差累积） | 受控（窗口间对齐抑制长程漂移） |
| 计算效率 | 较高 | 更高（窗口独立处理） |
| 推荐场景 | < 5000 帧 | > 5000 帧 |

## 6. 训练与数据

### 6.1 训练配置

- **两阶段训练**：
  - 第一阶段：160K 迭代
  - 第二阶段：160K 迭代
- **训练数据**：覆盖 29 个数据集（详见论文 Table 1）
- **损失函数**：
  - 深度损失（depth loss）
  - 绝对位姿损失（absolute pose loss）
  - 相对位姿损失（relative pose loss）
  - 相对位姿损失使用测地线旋转误差（geodesic rotation error）和 ℓ1 平移误差

### 6.2 数据生成管线

LingBot-Map 构建了大规模的训练数据生成管线，使用现有 3D 场景数据集渲染视频序列。

**源数据集**：
- **Matterport3D**：大规模室内场景扫描数据集
- **Gibson**：高保真室内环境数据集
- **HM3D（Habitat-Matterport 3D）**：大规模室内3D场景数据集

**相机轨迹生成**：
- 在场景的导航网格（navigation mesh）上采样路径点（waypoints）。
- 使用平滑路径生成算法创建自然的相机运动轨迹。
- 模拟手持相机的抖动和扫视（glance）行为：

**运动模型**：
- **基础运动**：沿路径的平滑移动，速度缓变并通过指数衰减平滑。
- **手持抖动**：在位置和方向上添加经 IIR（无限脉冲响应）滤波的高斯噪声。
- **随机扫视**：模拟人类行走时的自然视线转移，使用半余弦包络生成短暂的横向和纵向头部转动。

**参数多样化**：
- 每序列独立采样的相机参数，覆盖广泛的真实世界条件：
  - **水平视场角**：40° 至 100°
  - **传感器高度**：1.35 至 1.80 米
  - **行走速度**：0.3 至 1.8 米/秒
  - **抖动强度**：多档可选
  - **扫视频率**：多档可选
- 行走速度在序列内独立采样每段轨迹，产生自然的变速。

**渲染与输出**：
- 使用**针孔相机模型（Pinhole Camera Model）**。
- 分辨率：**640 × 480**，帧率：**30 FPS**。
- 每帧输出：RGB 图像 + 度量深度图 + 6-DoF 相机位姿（位置 + 四元数）+ 相机内参。
- 总生成：约 **2800 个序列**，每个 1000-5000 帧，共计 **14.4 TB** 数据。
- 所有参数和路径点坐标记录在配置文件中以确保完全可复现。

### 7.1 评估指标

| 指标 | 全称 | 描述 |

### 7.2 与现有方法的对比

LingBot-Map 在多个基准上与以下方法进行了对比：

| 对比方法 | 类型 | 特点 |
|---------|------|------|
| **TTT3R** | 流式方法 | 基于测试时训练（Test-Time Training）的3D重建 |
| **Wint3R** | 流式方法 | 基于窗口的3D重建 |

**关键对比结果**（具体数值详见论文 Table 2-4）：

### 7.3 消融实验

论文进行了系统的消融实验来验证各设计组件的有效性：

#### 三大注意力机制的消融

| 变体 | 描述 | 效果 |
|------|------|------|
| 无锚点上下文 | 移除锚点上下文 | 全局坐标定位能力显著下降，长序列漂移增加 |
| 无位姿参考窗口 | 移除位姿参考窗口 | 局部运动估计精度下降，短时一致性变差 |
| 无轨迹记忆 | 移除轨迹记忆 | 长程漂移校正能力丧失，误差随时间单调增长 |

**关键发现**：
- **Context Tokens 的重要性**：轨迹记忆中的上下文 token 是抑制长程漂移的关键。这些 token 保留了来自锚点帧和关键帧的几何信息，防止逐帧小误差复合为轨迹漂移。
- 三大注意力机制是**互补的**：它们分别针对不同时间尺度的几何推理问题。

#### 渐进式视图训练的消融

- 不使用渐进式训练时，长序列训练不稳定，早期误差传播导致模型发散。
- 渐进式课程训练是实现端到端长序列训练的关键技术。

### 7.4 鲁棒性分析

论文测试了 LingBot-Map 在不同条件下的鲁棒性：

- **不同场景类型**：室内（家庭、办公室）和室外场景。
- **不同运动模式**：步行、手持、快速移动。
- **不同光照条件**：明亮到昏暗。

结果表明 LingBot-Map 在广泛条件下保持了稳定的性能。

## 8. 结论与局限性

### 主要结论

1. **GCT 架构的有效性**：通过 GCA 注意力机制集成三种几何上下文，LingBot-Map 在流式3D重建任务上超越了现有方法。
2. **实时性能**：约 20 FPS 的推理速度使 LingBot-Map 可用于实时应用。
3. **长序列支持**：能够在超过 10000 帧的序列上保持稳定且精确的重建。
4. **前馈式方法的突破**：证明了精心设计的前馈式模型可以接近甚至达到迭代优化方法的精度。

### 局限性

- 在**极端动态场景**（大量运动物体）中性能可能下降。
- 对训练数据中**未覆盖的场景类型**泛化能力有限。
- 相机内参需要已知（不支持完全无标定的情况）。
- 当前主要针对**单目视频流**，对多相机系统的支持有待扩展。

### 未来方向

- 集成不确定性估计以自适应调整重建策略。
- 扩展对动态场景中运动物体的处理。
- 进一步提升推理速度以支持更高帧率。
